# EH3D-HYDRA-BRIDGE: not yet

Good ideas that are not in the current version. Writing them here keeps anybody from implementing them early or twice.

| Idea | Why not yet | Revisit when |
|---|---|---|
| Monitoring from A.R.M.O.R. | Out of scope; only the stability of the health and event points of the server matters | that ecosystem asks for it |
| A shared database between the two ecosystems | Each ecosystem keeps its own authority and its own data | a contract needs data that cannot travel in a message |
| Motion commands through the bridge | The machine and HYDRA-UMC keep the authority over motion, and the bridge is read-only for the cell state | the owner decides it explicitly, with a new decision record |
| Several adapters for one link | One adapter for the four links keeps the contract in one place | a link needs a different release cycle |
| A window for the bridge | The adapter talks to programs, not to people | a person needs to see the state of the links |
